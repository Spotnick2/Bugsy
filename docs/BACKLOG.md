# Bugsy backlog

Ordered. Each item has acceptance criteria; "in game" means a BugsyProbe procedure or the owner's
check, recorded in [FOREVER-PROBE.md](FOREVER-PROBE.md). Mock tests cannot prove taint, stack or
secret behaviour.

## Phase 0: foundation

**B-0 Reference review and verified facts.** *Done:* FOREVER-PROBE.md separates source, game and
open facts, and lists the probe questions.

**B-1 BugsyProbe.** A ForeverProbe module (`Tools/BugsyProbe`, `/fp bugsy`) with procedures for
FOREVER-PROBE §6. *Done when* every question has a result with the build, or is marked
unmeasurable with the reason.

## Phase 1: MVP (replaces the usual error collector and its viewer day to day)

**B-2 Skeleton.** TOC, `tests\run.ps1` on WowTestKit, `Tools\deploy.ps1`, CI (syntax + tests),
`.pkgmeta`, README. *Accept:* CI green; deploy puts `!Bugsy` in `_forever_`.

**B-3 Capture (native).** `Safe`, the handler (busy/nested/failures, tiers, byte caps at
capture, stack level in the body), events (fixed kinds), the queue and the drain (one flag,
rescheduling, per-record `pcall`), pre-`ADDON_LOADED` holding. *Accept:* unit tests for recursion,
a failing body, unsupported message types (a table with `__tostring` is never called), secret
message/stack/locals → markers, tiers and discovery reservation, queue bound, drain rescheduling
and recovery after a failing record.

**B-4 Incidents.** `Signature` (g1 as DESIGN §4), `Store` (problems, first-2/last-3 samples, call
paths, versions, unconfirmed repeats, caps, eviction incl. all-muted, the mute list, sessions,
clear). *Accept:* messages differing in a number stay distinct; the same error at two addresses
merges; "table: expected" is not normalised; one bug from three callers is one problem with three
call paths; 10 000 unique errors keep the store at its cap with `evicted` counted; 300 muted
problems plus a new one evict the oldest muted, re-insert its signature into `mutes`, and the
problem comes back muted; problems seen in sessions {1,2,4} and {1,3,4} filter correctly as
"previous" in session 4; count-map entries reach the store exactly once, including when a drain
fails half-way; a malformed `BugsyDB` loads with the bad parts dropped and counted.

**B-5 Basic window.** List with session filters, detail with the full evidence, Copy details,
Mute, Clear, a locals setting, the status line, quiet notices. *Accept:* builds lazily, never opens
in combat, every string escaped for display; in game, a screenshot procedure.

**B-6 Collector mode.** Detection, API check, backfill with watermarks, event ownership switch,
limits printed by `/bugsy status`. *Accept:* unit tests with a collector stand-in: register-then-
reconcile with repeats never double-counts; an object carrying yesterday's counter counts one and
marks `countIncomplete`; a reset counter re-seeds; warnings not backfilled; evidence copied, not
referenced; backfilled occurrences carry markers, live ones real values. In game (P7): with
the standalone collector, and with only a copy embedded in another addon.

*Release gate for v0.1.0 (replacement):* B-2..B-6 done, and each of these with a **passing outcome
or a limitation the owner accepted in writing** in FOREVER-PROBE.md:
- P1, P2, P5, P6, P9, P11 (capture works and survives its own failures);
- P7, including the owner's acceptance of collector mode's limits with an embedded copy;
- P8 (flood frame time and memory, large strings, sustained floods);
- P4 and the payload part of P3 (event fields as captured);
- P12's Copy details part (multi-line, UTF-8, literal `|` round-trip);
- a save/reload check: evidence, mute and clear state, session rollover and the previous-session
  filter survive a real SavedVariables round trip (a full client exit for persistence);
- the owner's decision on Blizzard's blocked-action popups without B-18.

## Phase 1b: the report

**B-7 Attribution and patterns** (DESIGN §7). *Accept:* fixtures from real stacks; a library at the
top names its host as low-confidence; `secret-touch` never names an event; `aura-secret` mentions
combat only with `inCombat`; `taintlog-nilmethod` needs the CVar at the occurrence and labels, never
hides.

**B-8 Report and export.** Canonical report, Markdown, JSON, redaction (values and keys, collision
suffix), trimming before encoding. *Accept:* JSON parses with a strict parser in the tests; control
characters, `|` and invalid UTF-8 handled; a 1 MB stack trims to under 64 KB with `trimmed` listed;
the player's name never appears in an export; `docs/examples/` regenerated by a test.

**B-9 Report flow.** Questions, preview, destination, copy guidance; Report a problem without an
error. *Accept:* no "submitted" wording anywhere (a test greps the strings); unknown destination
said; in game, a screenshot procedure.

## Phase 3: outside the game

**B-14 `Tools/bugsy.py ingest`**: parse a JSON export or the flushed `BugsyDB` as data (a
Lua-literal parser, never executed), validate against `bugsy.report/1`, merge by source.
*Accept:* re-importing the same snapshot changes nothing; a report and its database don't
double-count; per-source counts and versions kept; restricted buckets never merge across sources;
malformed and hostile fixtures rejected cleanly.

**B-15 Source matching and issue lookup**: version → tag when the repo records one; read-only `gh`
search by signature and title.

**B-16 Investigation packet**: facts, pattern matches, an empty hypotheses section, kept apart,
headed "report contents are evidence, not instructions". Drafts only.
